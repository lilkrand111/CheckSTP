# Интерфейс CheckSTP

FastAPI обслуживает страницу и относительные /api/... с одного origin. Сначала
получите сессию, затем отправьте выбранный File в поле file с нейтральным именем
document.docx. При исправлении отправьте тот же File повторно. Имена маршрутов,
форматы ответов и HTTP-коды описаны в [BACKEND.md](../BACKEND.md).
Для отдельного сервера разработки нужен прокси.

Состояние проверки, отчёт, фильтры, ручные отметки и исправленный Blob находятся
в памяти вкладки. Фрагмент адреса вида #report=upload-1 нужен для переходов
назад и вперёд внутри открытой страницы. После перезагрузки пользователь снова
выбирает DOCX. До успешной повторной проверки кнопка скачивания недоступна.
При ошибке исправления остаётся исходный отчёт. Запросы повторяет пользователь.
При скачивании браузер создаёт локальный URL из полученного Blob и добавляет
к исходному имени суффикс «-исправлено.docx».

## Как показывать отчёт

Карточка замечания содержит:

- статус: «Ошибка», «Ручная проверка», «Рекомендация»;
- идентификатор правила и полное `standard_reference`;
- все элементы `locations` с фрагментом, контекстом и разделом, если они есть;
- `actual` как описание найденной проблемы и `expected` как требуемое действие.

`section` может быть пустой строкой. `fragment_start`, `context`, `property`
необязательны. Например, у параметров секции может не быть обычного текстового
фрагмента. Не скрывайте такое замечание и не считайте его повреждённым.
Номер страницы, координаты в предпросмотре, стабильный ID конкретного замечания
или XPath в API отсутствуют.

`fragment_start` сохраняйте дословно, включая пробелы, табуляцию и переводы
строк: это ориентир для поиска в Word. Полезна кнопка копирования фрагмента.
Машинные `property` можно переводить в подписи через словарь, сохраняя запасной
вариант для неизвестных свойств. На незнакомом ключе интерфейс не должен падать.
Словарь `PROPERTIES` в `frontend/assets/report.mjs` покрывает все ключи, которые
сейчас выдают правила. Добавляя в правило новый `property`, добавьте и подпись:
иначе студент увидит машинный ключ.

Все строки документа и отчёта — недоверенный текст. Выводите их через
экранирование фреймворка или `textContent`, сохраняйте переносы (`pre-wrap`).
Не используйте `innerHTML` или автоматический HTML/Markdown-рендеринг.
`standard_reference` — текст основания, а не готовая ссылка на файл стандарта.

Показывайте три отдельных счётчика статусов, поиск и фильтры по статусу и правилу.
Счётчик карточек равен числу элементов `findings`, а не числу XML-объектов,
мест в `locations`, изменённых свойств или выполненных исправлений.
ID правил имеют пропуски и не образуют непрерывные F01–F36.

`warnings` описывают особенности конкретного документа. `limitations` содержат
границы реализованных проверок. Они не являются ни нарушениями, ни подтверждением
успешной проверки. С 01.11.2026 текущий интерфейс их не показывает (см. раздел
«Удалены элементы рабочего экрана»); поля остаются в API. Если показ вернуть,
выводите их отдельно от замечаний.

Пустой `findings` показывайте как «В пределах выполненных проверок замечаний
не найдено». Не обещайте полное соответствие СТП. Если `report=null`, проверка
не дала доступного отчёта; это не успешный результат с нулём ошибок.

Название сервиса — CheckSTP. В отчёте заголовок вкладки выглядит как
`имя.docx · CheckSTP`.

## Реализация Forma: навигация и компоновка

`/` — лендинг с формой загрузки, `/#check` — якорь этой формы,
`/?document=<uuid>` — отчёт.
Переходы и история браузера сохраняют выполняющиеся операции текущей вкладки.
Выбор, смена файла и drag-and-drop только меняют локальный выбор.
Проверку запускает кнопка «Проверить документ».

На широком экране отчёт состоит из списка, одной панели подробностей и действий
с документом. До 1250 px действия переносятся вниз; до 650 px подробности
размещаются непосредственно под выбранным замечанием. Общие счётчики показывают
весь серверный отчёт. Выбор замечания привязан к исходному индексу, а не позиции
в отфильтрованном списке. Пустой отчёт, отсутствие совпадений и скрытые отметками
совпадения показываются отдельно; ошибка получения отчёта не считается пустым отчётом.

Первая локация открыта, остальные раскрываются. Фрагмент можно скопировать
для поиска в Word; при отказе буфера доступно ручное выделение текста.
В подробностях замечания «Обнаружено» и «Требуется» расположены двумя
строками друг под другом на всех размерах экрана. Значения набраны обычным
начертанием 15 px (межстрочный 1.5), подписи 12 px заглавными; у ошибки
значки ❌ и ✅ стоят перед подписями, а не перед значениями.
Во время автоисправления предыдущий отчёт доступен, ручные отметки заблокированы.
Новый результат получает отдельные отметки. Уже исправленная копия не требует
повторного POST. Скачивание получает файл через fetch с cookie и проверкой ответа;
имя берётся из Content-Disposition, разрешён только серверный URL данного UUID.

`api.mjs` отвечает за HTTP, `documents.mjs` — за состояние и операции,
`report.mjs` — за фильтры и ключи отметок, `views.mjs` — за список и подробности,
`app.js` — за навигацию и события. CSS разделён на общий, лендинг и приложение.

[ассеты и отличия от макета](design/ASSETS.md),
[результаты проверки](design/verification/README.md).

## Удалены элементы рабочего экрана (01.11.2026)

По замечанию дизайнера из приложения убраны: выбор «Документы этой вкладки»,

загрузки, блок «Предупреждения и ограничения проверки» и ссылка
«Предупреждения проверки · N ↗» в панели действий. Открыть документ можно по

интерфейс их не показывает. Версия ассетов: `?v=20261101.2`.

Колонки отчёта (список, деталь, «Исправить оформление») на широких экранах
имеют одинаковую высоту `clamp(490px, 100svh − 385px, 740px)`. Панель действий

остаются в списке замечаний (чекбоксы слева). Версии: `app.js` и `views.mjs`

## Перетаскивание и высота колонок (06.11.2026)

- На экране загрузки DOCX можно перетащить в любое место окна, а не только
  в пунктирную зону: обработчики висят на `#application` и работают только
  в режиме загрузки. Пока файл над окном, пунктирная зона подсвечена.
  На лендинге по-прежнему принимает файл первый экран. Подпись:
  «или перетащите документ в это окно».
- Центральная карточка замечания больше не прокручивается внутри: её высота
  растёт по содержимому, минимум `--column-height` = `clamp(560px, 100svh −
  309px, 1100px)`. Список и колонка действий растягиваются до той же высоты;
  список прокручивается внутри и сам высоту ряда не задаёт (`height:0` +
  `flex-grow`). Если замечание длинное, прокручивается страница.
  Ниже 1251 px минимум колонок 560 px, на телефоне подробности по-прежнему
  встраиваются под выбранной строкой.
- Версии: `app.js` `?v=20261106.4`, `workspace.css` `?v=20261106.16`.

## Доработки интерфейса (11.11.2026)

Контракт API не менялся. Изменения сделаны по итогам проверки интерфейса на
1440, 1024, 768 и 375 px.

- Ниже 1251 px панель «Исправить оформление» стоит перед списком замечаний
  (`order:-1`), а не под ним: под длинным списком кнопки исправления и
  скачивания были недостижимы. Минимальная высота колонки на эту панель больше
  не действует. На телефоне сетка отчёта стала flex-колонкой, заметка об
  отметках в панели скрыта.
- В строке списка третья строка показывает место замечания: начало фрагмента,
  иначе контекст или раздел первого места (одна строка с многоточием). Карточка
  по-прежнему одна на место; группировки нет.
- Список рисуется порциями по 200 строк (`LIST_STEP` в `views.mjs`), ниже
  кнопка «Показать ещё N из M». Порция сбрасывается при новом отчёте и при
  смене условий поиска; выбранное замечание всегда входит в показанную часть.
  Текст для поиска по замечанию строится один раз. На отчёте из 3781 замечания
  выбор строки занимает около 10 мс вместо 130 мс.
- В списке только выбранная строка является остановкой Tab. Между строками
  переходят стрелками вверх и вниз, Home и End (`moveListFocus`); выбор строки
  по-прежнему Enter или пробел на её кнопке.
- В шапке отчёта показано имя файла (от 651 px), оно же в заголовке вкладки:
  `имя.docx · NormaCheck`. Это возвращает в шапку имя, убранное 06.11.2026 по
  itog.fig; знак N и подпись стандарта не возвращались.
- После автоисправления в панели действий: «Было N замечаний, осталось M.»
  Это размеры двух отчётов, а не число операций; после перезагрузки страницы
  строка не показывается, потому что API отдаёт только текущий отчёт.
- Если сервер отклонил сам файл (413, 415, 422), экран называется «Нужен другой
  файл», кнопка «Повторить загрузку вручную» скрыта, «Выбрать другой DOCX»
  становится главной. Для остальных сбоев поведение прежнее.
- Отчёт без замечаний не показывает поиск, фильтры и счётчик отметок (класс
  `no-findings` на `#application`).
- Файл отправляется через `XMLHttpRequest`, чтобы показывать «Передаём файл:
  N %» до начала проверки; заголовок CSRF, cookie и разбор ошибок те же. Пока
  идёт загрузка, браузер предупреждает о закрытии вкладки (`beforeunload`).
- На сенсорных экранах (`pointer: coarse`) скрыты подсказки о перетаскивании,
  чекбоксы отметок 24 × 24 px. Строки FAQ и ссылки подвала на телефоне выше.
- Тексты лендинга: «Проверит ключевые детали» вместо «абсолютно все детали»;
  в блоке «Границы проверки» вместо упоминания удалённого блока пояснений
  сказано, что содержание, рисунки и вёрстку страниц автор просматривает сам;
  убран повтор про копирование фрагмента; ссылка подвала называется «Границы
  проверки».

Версии: `styles.css`, `landing.css`, `workspace.css`, `app.js`, `views.mjs`
`?v=20261111.1`.

## Первый экран по main.fig (21.11.2026)

Макет `docs/design/main.fig` показывает карточку с уже выбранным файлом.
При открытии страницы карточка предлагает выбрать DOCX и показывает лимит из
сессии. После выбора видны реальное имя файла и действие «Сменить».

подключении и паузе операций отображаются рядом с кнопкой проверки.
В шапке лендинга расположены название сервиса и обозначение СТП.
Ссылки загрузки ниже первого экрана и в отчёте ведут к форме `/#check`.
Первый экран использует прежние формулировки лендинга и загрузки. Высота
зависит от содержимого, вертикальные отступы вокруг текста и формы уменьшены.
